  You're now onboarded with the OR-Q codebase - a plugin-based CLI tool for orchestrating command pipelines with AI
   model integration.

  What you now understand:

  Architecture: OR-Q uses a modular plugin system where commands process data in pipelines (string | Readable →
  string | Readable). The core consists of:
  - CLI (packages/cli/src/main.ts) - Entry point that loads plugins and handles I/O
  - Plugin Runtime (packages/core/src/index.ts) - Discovers and executes plugin commands
  - Library (packages/lib/src/index.ts) - Shared utilities and interfaces

  Key Commands:
  - pnpm run lint - TypeScript, ESLint, Prettier, Markdown checks
  - pnpm or-q <command> - Run commands in pipeline
  - pnpm or-q list-plugins - See available plugins
  - pnpm or-q list-assets - See YAML scripts and assets

  Plugin System: 16 plugins provide functionality from core commands (echo, tee, jp) to AI integration
  (@or-q/plugin-openrouter-api, @or-q/plugin-ollama) to YAML scripting (@or-q/plugin-yaml-script).

  Pipeline Examples:
  echo "Hello" | pnpm or-q tee              # Output to both stdout and pipeline
  echo '{"name":"test"}' | pnpm or-q jp "name"  # Extract JSON fields  
  pnpm or-q run fetch-test                  # Execute YAML scripts

  The codebase follows KISS/YAGNI/DRY principles and is in "functional prototype" phase, with clear architectural
  evolution planned in TODO.md.

Mental Model

- Program: Arguments = (string | Arguments)[] — a flat/nested token list.
- Pipeline: each command consumes args sequentially, returns string | Readable, passes along as input.
- Plugins: provide commands, assets, optional eventListeners; namespaced assets via plugin:<pkg.name>/path.
- YAML scripts: compiled into the internal program by @or-q/plugin-yaml-script. _JSON, _DATA, _RAW are directives

Execution Flow

- packages/cli/src/main.ts: parses argv, builds runtime, executes, streams output (Readable) or prints trimmed string.
- PluginRuntime.fromNodeModules(): discovers plugin packages (pattern) via installed-node-modules, imports default
plugin definitions.
- PluginRuntime.runCommands(stdin,inputArgs): loop
    - resolves command name via commandArgument()
    - runs command.run(input,args,runtime)
    - validates type (string | Readable), emits structured logs, displays a compact failing trace on errors.
- Events: loggingEventName, clone events, dynamic runtimeNewCommandAddedEventName.

Authoring Commands

- Use commandArgument(runtime, args.shift(), usage) to get required args.
- Convert streams via readableToString() when a full string is needed.
- Fail user‑visibly with fail(message) (throws PluginRuntimeFailure).
- Keep output compact JSON with trailing newline; commands should pass input unless they’re side‑effecting (print, tee).
- Constraints: optional/variadic flags don’t fit args.shift(); workaround only if !(args[0] in runtime.commands).

Assets

- Load module assets with loadModuleAssets(import.meta.url) and publish them (package.json files).
- Resolve: resolveAsset(), assetGlob(), resolveAssetSubdir() for per-subdir loading.

YAML Script Directives

- _JSON: injects JSON as command argument/input during compile; produces echo <json> in the internal program.
- _DATA: converts items to a JSON array argument at compile time.
- _RAW: inlines a command list inside another; reserved.

Key Packages
